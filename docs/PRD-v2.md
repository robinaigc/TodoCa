# 《我要移民啦》产品需求文档 V2（修订版）

> 修订日期：2026-07-04
> 本版本在原始文档基础上采纳全部 15 条修订意见。文中标 ✏️ 的位置为本次修订点，修订对照见文末附录。

## 0. 总指令

开发一个面向中文用户的加拿大登陆任务管理 App。

- 项目名称：我要移民啦（英文名 TodoCa）
- 副标题：加拿大登陆清单
- 核心功能：登陆前到登陆后 6 个月的中文任务清单
- 第一阶段目标：可上线的 PWA 手机网页 App
- 第一阶段城市：温哥华（BC 省）
- 第一阶段用户：中文使用者——留学生、工签人士、新 PR
- 核心体验：**用户打开 App 后 10 秒内知道自己今天该做什么**

不做资讯网站、不做论坛、不做文章库、不做移民百科。

---

## 1. 产品定位

这是一个**任务管理产品**。主入口是"今日任务"，不是文章、搜索框或商家黄页。

系统根据用户身份、登陆日期、家庭情况，自动生成五个阶段的个性化任务清单，每个任务提供：为什么做、所需材料、操作步骤、完成标准、常见错误、英文脚本、官方来源、人工协助入口。

### 1.1 MVP 明确不做的范围 ✏️

在原文档基础上，MVP 额外砍掉以下内容（原因见附录）：

1. **注册登录系统**（Supabase Auth、profiles 表、RLS）→ V1.1
2. **admin 管理后台** → 内容以代码内数据文件维护，线索在 Supabase 表格界面查看
3. **任务提醒功能**（"添加提醒"按钮）→ V1.1 以邮件提醒形式实现
4. **Service Worker 离线缓存** → PWA 只做 manifest（可安装到主屏幕）
5. AI 问答、多城市、支付、商家系统（原文档已排除，维持）

## 2. 目标用户与 Onboarding

### 2.1 三类用户

- 用户 A 留学生：保险、手机卡、银行、住宿、学校报到、交通、看病、英文脚本
- 用户 B 工签人士：SIN、银行、手机卡、医保、租房、入职、工资账单信用
- 用户 C 新 PR：COPR 材料、SIN、银行、省医保、租房、孩子入学、家庭医生、报税

### 2.2 Onboarding 问题（7 问，免注册）✏️

首次进入时收集以下信息，**保存在浏览器 localStorage，无需注册**：

1. 当前身份：留学生 / 工签 / 新 PR
2. 目的城市：第一版仅温哥华（省份由城市自动推导为 BC）
3. 登陆日期（预计或实际）
4. 是否已登陆
5. 是否带孩子
6. 是否已有长期住房
7. 是否有车或计划开车
8. （附加**多选**，至少选一项）当前最焦虑的问题，选项：
   a. 不知道先做什么　b. 租房　c. 医保和看病　d. 英语沟通
   e. 银行和钱　f. 孩子入学　g. 找工作　h. 其他

> ✏️ 修订说明：原 4.2 的 11 问精简为 7 问 + 1 个焦虑多选；删除"目的省份""是否带配偶""是否一个人登陆"（省份可推导，配偶在 MVP 中不影响任何任务的显示逻辑）；原 11–19 项的编号错乱已修正为选项 a–h。
> ✏️ 2026-07-04 增补：焦虑问题由单选改为**多选**（`topConcerns: TopConcern[]`），旧版本单选数据自动迁移为数组。

## 3. 阶段划分 ✏️

统一定义：**登陆日 = 第 1 天**，内部以 `landedDays`（登陆日为 0 的天数差）计算。

| 阶段 ID | UI 显示名 | 天数范围（landedDays） | 核心目标 |
|---|---|---|---|
| pre_landing | 登陆前 | < 0 | 带齐文件、预算、临时住宿 |
| week_1 | 登陆后一周（第 1–7 天） | 0–7 | 生存级基础设施 |
| month_1 | 登陆后一个月（第 8–30 天） | 8–30 | 临时生活 → 稳定生活 |
| month_1_3 | 登陆后 1–3 个月（第 31–90 天） | 31–90 | 建立本地生活节奏 |
| month_4_6 | 登陆后 4–6 个月（第 91–180 天） | 91–180 | 落地期收尾 |

- landedDays > 180：显示"落地期已结束"，历史任务仍可查看。
- ✏️ 修订说明：UI 阶段标签旁必须标注天数范围，消除"一个月"与"1–3 个月"的字面歧义；边界值归属已在上表明确，避免 off-by-one。

各阶段关键任务与原文档第 5 节一致（登陆前 13 项、一周 13 项、一个月 12 项、1–3 月 11 项、4–6 月 9 项要点），不重复罗列。

## 4. MVP 功能清单

### 4.1 首页：今日任务

展示：当前阶段与天数、阶段进度百分比、今日聚焦任务、之前阶段未完成的 P0 任务（补漏提醒）、高风险未完成任务、人工协助入口。

**✏️ "今日聚焦"的明确定义（原文档缺失）：**

> 当前阶段内、状态为未完成的适用任务，按「P0 优先 → 建议完成日（dayOffset）早者优先 → 高风险优先」排序，**取前 5 个**作为"今日聚焦"。不与真实日历硬绑定，避免"漏一天就挫败"的压力。

### 4.2 任务列表页

按五个阶段筛选 + 状态筛选：全部 / 未完成 / 必须做（P0）/ 建议做（P1）/ 高风险 / 可人工协助 / 已完成。

### 4.3 任务详情页 ✏️

包含：任务名称（中英）、适用身份、优先级、预计耗时、为什么要做、所需材料、操作步骤、完成标准、常见错误、英文脚本、官方来源、需要中文协助按钮、标记完成、暂时跳过。

> ✏️ 修订：删除"添加提醒按钮"（原 6.4 第 18 项），移入 V1.1 邮件提醒。

### 4.4 英文脚本库 ✏️

至少 30 条脚本，10 个分类（租房 / 银行 / 医保 / 学校 / 诊所药房 / 手机运营商 / 政府部门 / 快递地址 / 工作职场 / 通用沟通）。

每条脚本包含：中文场景、简短口语版、完整版、正式邮件版（如适用）、对方可能回答、听不懂时怎么说。

> ✏️ 修订新增：**每段脚本必须有"一键复制"按钮**——用户在柜台前可直接把句子递给对方看，这是真实高频场景。

### 4.5 新人地图（列表版）✏️

- 第一版做温哥华资源，**30–35 个精选资源点**（每类 3–5 个），验证后再扩量。
- 类别：政府机构（Service Canada / ICBC 等）、银行、药房、诊所、紧急护理（UPCC/ER）、图书馆、社区中心、华人超市、平价购物、交通、安置服务。
- 功能：类别筛选、详情页（地址 / 电话 / 官网 / 中文备注）、复制地址、打开 Google Maps 外链。不接地图 SDK。
- ✏️ 修订新增：每个资源详情页显示统一提示"**信息可能变动，出发前请打电话或查官网确认**"；数据结构预留 `lastVerified` 字段。

### 4.6 人工服务入口 ✏️

任务详情页与独立 /help 页提供"需要中文协助"入口，表单字段：姓名、邮箱、微信号（可选）、问题类型（租房 / 医保 / 账单 / 学校 / 银行 / 电话卡 / SIN / 孩子入学 / 看不懂英文邮件 / 其他）、问题描述、是否紧急、是否愿意付费咨询。

提交后写入 Supabase `service_leads` 表。**线索查看直接使用 Supabase Dashboard 的表格界面，不开发 admin 页面。**

> ✏️ 修订新增（隐私合规）：表单下方必须注明——"提交即同意我们通过邮箱/微信联系你，信息仅用于本次协助。"（PIPEDA / BC PIPA 要求）

## 6. 数据架构 ✏️（本次修订幅度最大的部分）

### 6.1 总原则

- **内容数据**（任务卡、脚本、资源点、阶段）：以 TypeScript 数据文件形式放在代码仓库内（`/data` 目录），有类型检查，改内容 = 改文件 + git push，Vercel 自动部署。**不放数据库。**
- **用户数据**（个人信息、任务进度）：浏览器 localStorage，键名 `todoca_profile_v1`、`todoca_progress_v1`。
- **线索数据**（service_leads）：唯一的服务端数据，存 Supabase Postgres。

> ✏️ 修订说明：删除原文档 8.1 users、8.2 profiles、8.5 task_identity_rules、8.6 task_progress（服务端版）、8.10 admin_users 五张表；tasks/scripts/resources/stages 由数据库表改为代码内数据文件。第 9 节 RLS 要求随之大幅简化。

### 6.2 任务数据结构（代码内，替代原 8.4 + 8.5）

```ts
interface Task {
  id: string;
  titleZh: string;
  titleEn: string;
  stageId: StageId;
  priority: "P0" | "P1" | "P2";
  highRisk?: boolean;
  serviceable?: boolean;          // 是否显示"需要中文协助"
  serviceCategory?: string;
  identities: IdentityType[];     // ✏️ 数组字段替代 task_identity_rules 表
  estimatedTime: string;
  dayOffset: number;              // 建议完成日（相对登陆日，负数=登陆前）
  shortDescription: string;
  whyItMatters: string;
  requiredDocs: string[];
  steps: string[];
  completionStandard: string;
  commonMistakes: string[];
  officialSources: { name: string; url: string }[];
  englishScript?: string;
  conditions?: {                  // ✏️ 新增：16.2 过滤逻辑所需的条件字段（原文档缺失）
    requiresChildren?: boolean;   // 仅带孩子用户可见
    requiresNoHousing?: boolean;  // 仅未有住房用户可见
    requiresCarPlan?: boolean;    // 仅有车/计划开车用户可见
  };
}
```

### 6.3 service_leads 表（Supabase，唯一数据库表）

```sql
create table service_leads (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  email text not null,
  wechat text,
  identity_type text,
  city text default 'Vancouver',
  category text not null,
  urgency text default 'normal',
  willing_to_pay boolean default false,
  description text not null,
  related_task_id text,
  status text default 'new',      -- new / contacted / scheduled / closed
  created_at timestamptz default now()
);
```

RLS：启用 RLS；匿名角色只允许 INSERT，不允许 SELECT/UPDATE/DELETE（线索只能提交，不能被前端读取）；运营者通过 Supabase Dashboard 查看。

## 7. 核心逻辑

### 7.1 阶段计算 ✏️（边界已修正）

```
landedDays = floor((今天 00:00 - 登陆日 00:00) / 1 天)
landedDays < 0        → pre_landing
0 ≤ landedDays ≤ 7    → week_1
8 ≤ landedDays ≤ 30   → month_1
31 ≤ landedDays ≤ 90  → month_1_3
91 ≤ landedDays ≤ 180 → month_4_6
landedDays > 180      → 落地期结束（仍可查看任务）
```

### 7.2 任务过滤

任务对用户可见，当且仅当：

1. `task.identities` 包含用户身份；且
2. `conditions.requiresChildren` 为 true 时用户带孩子；
3. `conditions.requiresNoHousing` 为 true 时用户未有住房；
4. `conditions.requiresCarPlan` 为 true 时用户有车或计划开车。

### 7.3 排序与进度

- 排序：P0 → P1 → P2；同级中当前阶段优先；再按 dayOffset 升序；再高风险优先。
- 阶段进度 = 当前阶段已完成数 / 当前阶段适用任务总数。
- 同时展示：总任务数、已完成、已跳过、高风险未完成。

## 12. 验收标准

### 12.1 用户流程

打开首页 → 完成 onboarding（免注册）→ 生成个人清单 → 查看今日任务 → 查看全部任务 → 查看任务详情 → 标记完成/跳过 → 查看阶段进度 → 查看/复制英文脚本 → 查看资源列表并打开 Google Maps → 提交人工协助请求 → 修改个人资料。

### 12.2 数据

≥ 50 任务卡、≥ 30 脚本、30–35 资源点、5 阶段、3 身份；任务进度本地可保存；线索可写入 Supabase 并在 Dashboard 可见。

### 12.3 移动端

iPhone / Android 常见宽度显示正常；底部导航可用；按钮足够大；中文排版舒适；可"添加到主屏幕"。

### 12.4 闭环

每个 P0 任务包含：为什么做、所需材料、步骤、完成标准、常见错误、英文脚本、官方来源、人工协助入口。

### 12.5 成功指标 ✏️（替换原第 24 节中不可测量项）

- Onboarding 完成率 ≥ 70%
- 次日留存 ≥ 30%
- 人均任务完成 ≥ 5 个
- 人工协助线索 ≥ 5 条
- 付费意愿线索 ≥ 3 条

核心检验：用户打开 App 后能否立刻回答"我今天该做什么"。

## 13. 版本规划

- **V1.0（本文档）**：温哥华 MVP——个性化清单、任务详情、脚本库、资源列表、人工协助线索。
- **V1.1**：注册登录 + 云同步（此时注册是价值不是门槛）、邮件任务提醒、Service Worker 离线缓存、AI 问答、截图解释。
- **V1.2**：多伦多、卡尔加里、城市切换、商家目录初版、内容管理后台（如内容更新频率需要）。
- **V2.0**：商家合作、服务订单、Stripe 支付、原生封装。
